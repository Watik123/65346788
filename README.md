# Справжні знижки

Сервіс-агрегатор, що показує товари, які **реально** подешевшали: ціна нижча за типову
ціну ринку за останні 30–60 днів, а не за закреслену ціну магазину.

Статус: **етап 1 з 6** — каркас, база даних, тестові дані.

## Що потрібно

- Node.js 22 або новіший (`node -v`)

## Швидкий старт

```bash
npm install          # ставить залежності й генерує Prisma-клієнт
npm run db:setup     # створює базу data/app.db і наповнює її тестовими даними
npm test             # перевіряє, що тестові дані правильні
npm run db:studio    # відкриває базу в браузері для перегляду
```

Файл `.env` необов'язковий: без нього база лежить у `data/app.db`. Зразок — `.env.example`.

## Команди

| Команда | Що робить |
|---|---|
| `npm run db:setup` | застосовує міграції й запускає сид (для нової копії проєкту) |
| `npm run db:seed` | перезаписує тестові дані (повторний запуск безпечний) |
| `npm run db:reset` | видаляє базу, створює заново й наповнює |
| `npm run db:migrate` | створює нову міграцію після змін у `schema.prisma` |
| `npm run db:studio` | перегляд бази в браузері |
| `npm test` | тести |
| `npm run typecheck` | перевірка типів |

`SEED_TODAY=2026-10-03 npm run db:seed` фіксує дату «сьогодні» в тестових даних.

## Структура

```
apps/api/             бекенд: Fastify + Prisma
  prisma/schema.prisma   модель даних
  prisma/migrations/     історія змін бази
  prisma/seed/           тестові дані (каталог, генератор історії цін, тести)
  src/lib/               підключення до бази
data/                 SQLite-файл і (згодом) сирі відповіді парсерів, не потрапляє в git
```

## Тестові дані

54 товари в 6 категоріях, 6 магазинів, 90 діб історії цін. Бренди й моделі реальні,
**ціни, оцінки, відгуки й наявність вигадані**, посилання ведуть на `example.com`,
штрихкоди з префіксом 200 (службовий діапазон, не збігаються з реальними).
Не публікувати як справжні дані.

У кожного товару закладений сценарій цінової історії, за яким перевірятиметься скор:

| Сценарій | Кількість | Очікуваний результат |
|---|---|---|
| справжня знижка (ціна впала на 11–22%) | 17 | знижка підтверджена |
| фейковий підйом (ціну підняли й «знизили» назад) | 7 | знижки немає, хоча магазин обіцяє 14–21% |
| нестабільна історія (ціна стрибає) | 3 | знижка не підтверджена |
| повільне здешевлення | 6 | мала справжня знижка (2–4%) |
| стабільна ціна, частина з постійною «акцією» магазину | 18 | знижки немає |
| новий товар (історія 7–11 діб) | 3 | недостатньо даних |

## PostgreSQL

Схема не використовує `enum`, `Json`, `Decimal` і сирий SQL, тож перехід зводиться до
заміни `provider` у `schema.prisma`, адаптера в `src/lib/db.ts` і повторної міграції.
Це ще не перевірено на реальному PostgreSQL.
